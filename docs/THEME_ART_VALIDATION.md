# 主题与诗画关系：Skill 验证计划

2026-10-28。基线：`feat/video-v2` / `8194e65`；实验分支：`feat/theme-art-validation`。

目标：在 weshici-skill 验证「背景默认随主题、画风允许独立、景物由诗意决定」，形成可复现的配方与样张，验证后再迁移 App。本轮不修改 Swift 或 App，不发布内容。

## 1. 先厘清现有能力

- `poster`：独立 Canvas 山水，已接七套主题色及浅深模式；画的设色随主题派生。不是 shanshui@5，也不是花卉引擎。
- 视频 v2：动态画屏、水墨叙事、诗词 MV 已接 shanshui@5；诗人行迹和文档收尾仍是原分支后续工作。
- `nonflowers@2`：Web 引擎已随包提供，需验证实际入口、题材路由与诗句框，不能把存在底层代码当作产品入口已完成。
- 现有 Web shanshui 快照是否具备原生五画风笔法，以代码和样张核对；换 palette 不能算完成青绿、金碧或没骨笔法移植。

## 3. 待验证的行为规则

1. 未指定画风：使用主题推荐的绘画配置，题材仍由诗意决定。
2. 明确指定画风：保留用户的选择；纸色与文字随主题，画的固有色只做必要的明暗适配。
3. 素纸：保留排字与纸感，关闭景物。
4. 已保存作品：使用当时解析后的具体配方，不因全局主题或日期变化而重算；新作才使用新的默认值。
5. `seasonal` 在导出时解析并记录具体主题与日期。复现条件包含种子、引擎版本、尺寸、字体、主题与画风，不能仅凭种子声称相同。

这些规则已在独立 Skill 实验入口实现，尚未作为全局产品规则上线。避免把文案中的“主题”（一组诗的策划标题）与视觉主题混为同一字段。
